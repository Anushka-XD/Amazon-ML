### Measurements that redirected the work

- **61.6% of missed truth pairs were generated by the join and then dropped by a cap**; only 0.0%
  were signal-absent (both addresses missing / script mismatch). Recall was a *configuration*
  problem, not a data problem.
- **Romanization is a weak bridge.** Across 6 schemes on 614 real cross-script pairs, mean fuzz
  was 61-68 and only **9.9%** shared a romanized token (36.5% a 5-char prefix). The address is the
  real bridge: **97.5%** of cross-script pairs share an address token, statistically
  indistinguishable from Latin pairs (95.4%).
- **Usable-key ceiling, measured properly.** An earlier "0.989 ceiling" counted any shared
  street token, including `rue`/`main` whose blocks always exceed the per-pass cap and are
  therefore always dropped. Restricting to tokens whose block actually survives gives a
  materially lower ceiling than first claimed.
- **Per-S1 cap is the binding constraint, not the keys.** Recall saturates at ~0.884 across
  cap 200 -> 3200; candidates/S1 flattens at ~235. Widening block caps *lowered* recall to
  0.7563 because `ORDER BY pass_id` let address collisions evict name matches.
- **Street-token rarity gate does nothing**: idf>=4.0 -> 0.8836, idf>=2.0 -> 0.8829, no gate ->
  0.8818.
- **Dense retrieval separates cleanly.** `intfloat/multilingual-e5-small` on real data: true
  cross-script pairs mean cosine **0.929** (p10 0.890) vs unrelated **0.822** (p90 0.850);
  84.9% of true pairs clear 0.90 where 0.0% of unrelated pairs do.
- **The decisive test** (`exp_missed_retrievable.py`): of the truth pairs blocking *currently
  misses*, **100%** clear cosine 0.85 and 96.3% clear 0.90, mean 0.965. So the residual recall
  gap is a *similarity-measure* gap, not absent signal.
- That same test exposed a self-inflicted bug: missed pairs included **identical names** at
  cosine 1.000, dropped because `n_passes DESC` let a 5-pass fuzzy pair outrank an exact-name
  match and push it outside the per-S1 cap. Ranking corrected to
  `block_score DESC, n_passes DESC`.

### Bugs found and fixed in our own new code

- `calibration.score` scored matched-but-unproposed entities as free 1.0 singletons, which would
  have silently inflated every F0.5 reported. Now requires `n_true_by_s1` and is pinned by tests.
- `_join_sql` applied the shard predicate downstream of the join, so every shard joined the full
  key set — sharding was a no-op. Moved onto the Source 1 side, before the join.
- The `valid` block-size aggregate ran over all ~50M candidate keys per shard; restricted to
  probed keys first (145M keys -> 5.7M valid blocks in 27 s).
- `block_keys` emitted street keys from `street_tokens[0]`, which is a grammatical particle in
  French and a filler in many Indian addresses.
